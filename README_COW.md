# OSRS Cow Combat Bot

依 `fight_cow_document.odt` 製作的獨立打牛版本，不修改 Chicken Bot。
適用於 **Windows、官方 Old School RuneScape client、1920x1080 桌面、
最大化視窗、100% 縮放及提供截圖中的介面配置**。不需要 RuneLite、OCR
服務、遊戲記憶體讀取或網路 API。

> 自動化操作可能違反遊戲規章並導致封號。這是需人工監督、先校準再執行的
> 視覺自動化原型，不是經過實機驗收的無人值守產品。請自行評估使用風險。

## 安裝及離線驗證

需要 Python 3.10+，在本目錄執行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe cow_bot.py init
.\.venv\Scripts\python.exe -m unittest -v test_cow_bot
.\.venv\Scripts\python.exe cow_bot.py inspect images\before_take_cowhide.png
.\.venv\Scripts\python.exe cow_bot.py replay full_attack_cow_and_take_cowhide.mp4 --client-video
```

`init` 從現有圖片及存倉影片產生 `cow_profile` 中的原生字模、物品欄模板、
HUD、右鍵選單及銀行特徵；保留已校準的骨頭模板、路線、設定與額外字模。
測試使用獨立暫存 profile，不改動個人校準。

錄影的尺寸並不一致：戰鬥及回程片段是 1920x1012 的 client 畫面；
`--client-video` 明確補上 23px 標題列位置供唯讀回放，不縮放像素，
也不把這個轉換套用到實機點擊。背包被隱藏時會輸出
`inventory: null` 及 `inventory_error`，不會當作空背包。
行走影片是 1914x1078，不能直接當作目前實機座標；需另行校準。

## 先做被動觀察

```powershell
.\.venv\Scripts\python.exe cow_bot.py observe --seconds 30
```

倒數五秒內切換到最大化 OSRS。此模式**不移動滑鼠、不點擊、不按鍵**。
手動打牛，檢查輸出的 `hover`、`health`、`hud_clear`、`inventory`。
視窗失焦、解析度不同或無新畫面時會停止。

拾取模式啟動時若背包未開，或運行中發現面板消失，程式會先驗證背包分頁圖示，
移至分頁後只點擊一次，並要求背包面板及
兩次一致的物品格讀數確認重開，才繼續拾取或尋找下一個目標；若圖示無法辨識、
面板未重開或物品格讀數不一致，仍會安全停止。`INVENTORY_REOPENED` 事件會
記錄重開及當時的牛皮、骨頭、空格數量。拾取模式只接受所選物品及空格；
背包面板與分頁可在基準位置上下 12px 內辨識，並使用辨識到的偏移讀取物品格及點擊分頁；
超出範圍或位置不唯一時會安全停止。
圖片中的羽毛、其他物品會被視為未核准內容，必須先自行存放。
這項限制防止 Deposit inventory 一併存走食物、工具或其他物品。
不會自動吃食物、補血、復活、重新登入或處理隨機事件。
請先確認人物能安全承受戰鬥，不要無人看管。

## 校準往返銀行路線

```powershell
.\.venv\Scripts\python.exe cow_bot.py record-route
```

錄製工具**只截圖和記錄，不會移動滑鼠或操作遊戲**。請完全依照 PowerShell 每步提示：

1. 先輸入牛欄到銀行的預估步數。每段行路、每道閘、每段樓梯各算一步；最後開銀行也算一步。接著逐步錄製。若實際步數比預估少，在下一步提示輸入 `finish`，即可結束**整趟往返錄製**，不必補足預估步數。
2. 每一步開始時，先站在遊戲起點。一般動作把滑鼠停在目的地；樓梯動作則先右鍵樓梯並保持選單打開（左上角沒有文字是正常的），再回 PowerShell 按 Enter。倒數 5 秒期間保持 OSRS 在前景和畫面穩定。
3. 程式保存起點截圖後，會開「截圖預覽」視窗。只在這個預覽視窗拖曳方框，選起點附近清楚固定的景物，放開後按 Enter/Space。再於目的地預覽圖的**綠框內**按一下記錄目的地座標。綠框涵蓋整個 OSRS 遊戲視窗客戶區，不包括 Windows 標題列和工作列；它不是每步距離或總步數限制。預覽圖縮放後，程式會自動把點擊座標換算回原始截圖大小；這一下不會操作遊戲。路線地標仍只在遊戲場景區搜尋，避免在介面上誤認地標。
4. 一般動作只需輸入起點截圖左上角斜線前的完整文字，例如 `Walk here`、`Open Gate` 或 `Bank Bank booth`；若後面有 `/ N more options`，尾碼可略過，程式只會比對斜線前的動作文字。樓梯不同：截圖前先右鍵樓梯並保持選單打開，左上角空白是正常的；輸入 `Climb-up Staircase` 或 `Top-floor Staircase` 表示上樓，輸入 `Climb-down Staircase` 或 `Bottom-floor Staircase` 表示下樓。之後還要在截圖預覽中**另框一次**單獨的 `Top-floor Staircase` 或 `Bottom-floor Staircase` 選單列；`Climb-up Staircase`／`Climb-down Staircase` 是另一列，不要一起框。這和前面選起點地標是兩個不同框選。樓梯列高度較小是正常的；若選框太小或包含多列，程式只會要求重選選單列，不會中止錄製。程式會保存該列，執行時右鍵樓梯並只在確認同一選項列後才點選。完整截圖保存在輸出路線的 `_assets` 資料夾。
5. 回遊戲手動完成**這一個動作**並等角色到達目的地，再回 PowerShell 按 Enter。於抵達截圖預覽視窗框選一小塊固定地景；它必須與移動前同一位置不同。
6. 設定程式日後執行該步時的到站等待上限：行路輸入 `15`（可調至最多 `45`）；樓梯輸入 `5`。每次提示只輸入一個數字再按 Enter，直接按 Enter 使用提示中的預設值。這不是要求你現在等待的時間。
7. 去銀行最後一步必須是 `Bank Bank booth`。到銀行後由你手動存倉和關銀行，再按提示輸入回牛欄步數並以同樣方式記錄回程。若把整趟往返連續記錄在同一方向，`finish` 會在唯一的 `Bank Bank booth` 步驟後自動拆分去程和回程；若開銀行後沒有任何回程步驟，程式會要求補完，不會保存不完整路線。

例如 timeout 提示後只輸入 `15` 然後按 Enter；不要把「行路 15 秒」等說明文字打進去。`finish` 只在「第 N 步」提示時輸入；它會結束整趟錄製，不會代替任何遊戲動作。若其中一個方向尚未錄完，程式會拒絕儲存。若視窗被遮住，按 Alt+Tab 尋找標題含「截圖預覽」的視窗。

每完成一步，路線資料會自動保存到同名的 `.progress.json` 進度檔。若某一步出錯，PowerShell 會列出失敗方向、未完成步數、已保存步數、可查看的截圖路徑，以及可直接複製的相同續錄命令。重新執行該命令後，程式會顯示相關截圖並從該步繼續；未完成的步驟會重錄，已完成的步驟會保留。中途關閉後重新執行也會顯示續錄位置。成功產生正式路線後，進度檔會移除。若同名正式路線已存在，才需要另選新的 `--output` 名稱。

執行時會重新尋找唯一地標、重新確認 hover，並在最後一張畫面再次檢查地標。
只有連續三張新畫面符合到站特徵才進入下一步，不使用固定延遲當作已抵達。
門已開且到站特徵相符可略過開門步驟；相機、縮放、門狀態或地景不同導致
無法證明位置時會停止，**不盲點、不猜路、不自動無限重試**。

路線必須覆蓋實際起點附近可見的地標；不是通用尋路器，不能保證從牛欄的
任意位置都能找到第一個節點。請先保持相機角度並在選定範圍內測試。
若重新錄製已完成的路線，請使用新的 `--output` 檔名；未完成的路線則用原本指令續錄。

## 骨頭模式的額外校準

現有素材沒有可確定的背包 Bones 圖示，不能假造識別能力。
若要使用骨頭模式，手動取得骨頭並截取同配置的完整畫面：

```powershell
.\.venv\Scripts\python.exe cow_bot.py calibrate-bones my_bones.png --slot 1
.\.venv\Scripts\python.exe cow_bot.py inspect my_bones.png
```

`--slot` 是由左至右、由上至下的 1–28 格。請確認該格確實只有 Bones，
且檢查結果正確；沒有此校準，骨頭相關模式會拒絕執行。
拾取時打開右鍵選單，僅點擊嚴格像素匹配的 Take Cowhide / Take Bones 列，
不會選擇 Take Raw beef。

## 明確授權後執行

### 測試啟動前的強制提醒規則

- 每次要求使用者開始遊戲測試前，必須先以獨立、醒目的 ALERT 提醒，
  不可只在長篇說明中附帶提及倒數。終端機必須先輸出醒目的 `ALERT`，
  再逐秒顯示 `5、4、3、2、1`，每個數字間等待一秒，總共提供完整五秒：
  **「ALERT：實機控制即將開始。請切回最大化 OSRS；倒數結束後不要移動滑鼠；
  有異常按 F8 停止。」**
- 提醒必須放在啟動指令之前；不得未預告就代為啟動測試或開始倒數。
  若由助手代為啟動，必須先取得使用者已準備好的明確確認。
- 程式必須在五秒逐秒倒數期間不發送遊戲操作；倒數結束仍未切回遊戲，
  應安全停止，不得對其他視窗操作。被動模式須明確說明不會送出任何輸入。
- 此規則同樣適用於被動觀察、實機戰鬥及路線校準的倒數截圖。
  被動觀察及路線校準不會自動發送遊戲操作。
- 目前提示形式為終端機 `ALERT` 與逐秒 `5` 至 `1` 倒數；未實作彈出式視窗
  或聲音提醒，不可將上述規則描述為這些功能已完成。

```powershell
.\.venv\Scripts\python.exe cow_bot.py run --live --mode COWHIDE_ONLY --max-kills 10
```

可選模式：

- `COWHIDE_ONLY`：只撿牛皮，預設選項。
- `BONES_ONLY`：只撿骨頭，需額外校準。
- `COWHIDE_AND_BONES`：兩者都收，需額外校準。
- `COMBAT_ONLY`：完全不撿取，不需要銀行路線。

不指定 `--mode` 會在每次啟動詢問。沒有 `--live` 不會發送操作。
拾取模式預設必須有完整校準路線；可用 `--route cow_profile\route_v2.json` 指定。
首次只測一隻牛、不測銀行時，可明確使用 `--no-bank`：

```powershell
python cow_bot.py run --live --mode COWHIDE_ONLY --max-kills 1 --no-bank
```

此選項不載入銀行路線，即使已存在路線也不會使用；背包滿會 `SAFE_STOP`，
不導航、不存倉。建議清空背包、手動開啟背包並站在牛欄內再啟動。
倒數五秒內切回遊戲，之後不要操作滑鼠；有異常按 F8。
一次擊殺後仍會嘗試拾取，再輸出 `KILL_LIMIT_REACHED`；不保證一定找到牛皮。
預設最多擊殺 10 次，到達上限便停止，不是無限制循環。

**F8、Ctrl+C、移動滑鼠至左上角、手動移動滑鼠或切走遊戲視窗都可停止。**
執行期間不要同時操作滑鼠；觸發停止後需重新啟動。
若前景檢查安全停止，錯誤會列出 Windows 回報的前景視窗標題及最小化狀態；
遊戲畫面出現在截圖中本身不足以證明它是前景視窗。

## 核心驗證契約

- 先確認舊 HUD 已清除，再以兩張新畫面確認 Attack Cow / Cow calf。
- 點擊前直接比對 hover 像素；任何變化均不點擊。
- 點擊攻擊後，先觀察玩家錨點附近 64x80 區域；連續七張新畫面中，
  灰階差異大於 40 的像素數不超過 80，才視為角色停定，並從該刻開始
  等候 10 秒內出現正血量。
  錨點使用 `cow_profile/settings.json` 的 `player_anchor`，預設為 `[942,520]`；
  若遊戲人物不在此螢幕位置，需先按人物中心校準，否則停定判定不可靠。
  停定偵測最多 30 秒；看見正血量後，連續兩張新畫面的 0 HP 才確認擊殺；
  停定後戰鬥超過 30 秒或 HUD 目標切換立即停止。
- 正血量以核准目標 HUD 的綠色血條及數字存在確認；0 HP 使用原生零字模。
  不將「HUD 消失」當成死亡，也不讀頭頂血條。
- 攻擊前會先檢查目標點周圍是否已有頭頂戰鬥血條（30×5px 亮綠／亮紅），
  若已有血條代表其他玩家正在戰鬥中，會直接略過並將該點周圍 36px 範圍
  加入 20 秒黑名單，改找下一隻牛。
- 點擊後若聊天區新增或捲動出新的「Someone else is fighting that」訊息
  （含聊天框已滿時的新增捲動），同樣將該點周圍 36px 範圍加入 20 秒黑名單；
  普通 `ATTACK_MISSED` 不會封鎖目標。
- 牛皮及骨頭按獨立背包格數計數，不讀堆疊數字。
  拾取後必須連續兩張畫面驗證「指定物品 +1、空格 -1、其他物品不變」。
- 若拾取模式的背包面板暫時消失，先以固定介面位置的背包圖示雙重視覺守衛
  重開一次，確認面板及連續兩次相同的格數後才繼續；若無法確認就安全停止。
  重開行為留存 `INVENTORY_REOPENED` 事件；純 `COMBAT_ONLY` 不讀取或重開背包。
- **最新掉落物搜尋規格**：搜尋中心必須使用本次成功擊殺目標的最後確認攻擊點，
  不再固定以玩家位置作中心；只有沒有本次擊殺點時才可退回 player anchor。
  Cowhide 在已保存畫面中呈淺灰白、帶紅棕色細節，因此 ROI 使用 HSV
  `[0,0,160]`–`[20,50,255]` 遮罩，再用紅棕細節、`findContours` 面積
  在該色塊的輪廓內、中心 ±5px 範圍隨機抽樣；若在中心 48px 內遇到被角色部分遮蔽
  的較小色塊（`35 <= area <= 80`）也會列入次優先候選。移向 Cowhide 時分段調整速度，
  可能微幅越過目標後修正；選取前加 200–450ms 截斷常態分佈延遲。候選按距離排序並逐一 Hover；
  顏色只作提名，仍須核對 `Take Cowhide`／`Take Bones` 懸停文字、右鍵選單
  及背包增量。Cowhide 只由色塊候選搜尋，`COWHIDE_ONLY` 不啟用螺旋後備，
  並在 25 秒總期限內持續檢查新畫面；若 2 秒後仍未抓到色塊候選，會主動 Hover 探測
  玩家正上方及擊殺點附近的遮蔽位置，若掃完且超過 10 秒仍無候選便結束該輪搜尋。
  `BONES_ONLY` 保留螺旋搜尋，雙物品模式的
  螺旋後備只接受 Bones，不會用它搜尋或拾取 Cowhide。
  Bones 螺旋搜尋以中心由內而外：中心 48px 範圍採 12px 間距，
  外圈至 130px 採 24px 間距。共用 25 秒總期限，每個位置只等候下一張新畫面，
  背景取幀等待間隔為 50ms；加快掃描但保留原搜尋點距及覆蓋範圍，CPU 使用量會增加。
  不因單點而延長期限；
  移動或取幀已超時時不得用該點執行拾取。若期限內已確認目標物品懸停文字，
  即使讀取背包時期限剛過，仍會完成該物品的選單驗證及拾取確認，不會丟棄已找到的候選。
  只搜尋目前模式允許的物品；`hover_matches` 只計算這些目標，其他掉落物另記為
  `ignored_item_matches`。選單驗證失敗會記錄 `PICKUP_MENU_REJECTED` 和原因，
  右鍵後最多輪詢 1 秒等待選單列出現；仍須通過選單列、連續兩張新畫面及最後畫面守衛
  才可左鍵點擊，不得只因搜尋排序或目標文字而宣稱拾取成功。
  `COWHIDE_ONLY` 一旦通過背包增量驗證，立即停止該輪搜尋，並以
  `stop_reason=target_collected` 記錄；骨頭及雙物品模式不套用此提前結束規則。
  `LOOT_SEARCH_FINISHED` 必須記錄中心、細掃／粗掃探點數、總探點數、符合拾取文字數、
  色塊候選數、已掃最遠距離、耗時及停止原因；這些搜尋指標不等同拾取成功。
- 滿 28 格後走去銀行，確認銀行已開、Deposit inventory 提示及最後像素守衛，
  才單次存倉；確認連續兩張畫面 28 格全空後關銀行並走回牛欄。
- 五次連續搜尋／攻擊失敗停止；HUD 清除 15 秒、找牛 30 秒、
  角色停定偵測 30 秒、停定後等候目標血條 10 秒、戰鬥確認 30 秒、找物品 25 秒、
  點擊後拾取驗證 15 秒、存倉驗證 4 秒皆有界限。拾取期限容許角色走到掉落物；
  找牛期限從 HUD 清除後開始計算；
